# 股票交易账本 PWA

一个可添加到 iPhone 主屏幕的零后端网页应用。包含：买卖记录、分账户持仓、按移动加权平均成本的已实现盈亏、历史盈亏、筛选、CSV 导出、JSON 备份和恢复，以及离线缓存。

## 部署（推荐 GitHub Pages）
1. 新建 GitHub 仓库，把本目录内的所有文件（不是文件夹外层）上传到仓库根目录。
2. 仓库 Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save。
3. 打开 GitHub Pages 显示的 HTTPS URL。iPhone Safari → 分享 → 添加到主屏幕。
4. 首次需要在线访问；资源缓存成功后可以离线打开。

也可部署到 Cloudflare Pages / Netlify 等静态网站托管平台，必须是 HTTPS（localhost 除外），否则 Service Worker 不能离线运行。直接使用 file:// 打开不支持完整 PWA 功能。

## 注意事项
- 所有交易数据保存在当前浏览器/主屏幕网页 App 的 localStorage；不会自动云同步，请定期导出 JSON 并保存在 iCloud Drive。
- iOS 上 Safari 和主屏幕 PWA 的存储可能相互隔离，以安装后的 App 为准；删除 App、清理网站数据等操作可能导致丢失。
- 不接入券商，不提供行情、资产市值或投资建议。
- 首次运行预置 5 笔历史盈亏：出版传媒 +7635、鼎信通讯 +15573、南京港 +17300、新华都 +35700、读者传媒 +54900，共 +131108 元。这些记录只有盈亏金额，无交易时间/成交价。
- 盈亏以移动加权平均成本计算；仅追踪通过本 App 录入的完整历史。开始记录之前已有的真实持仓，需先录入实际买入成本与时间，否则后续卖出可能被禁止。
- 可删除记录，但如果导致后续卖出数量超过历史持仓，则拒绝删除。

## v2 新增功能（2026-10-15）
- **持仓天数**：未卖出的股票显示持有天数；卖出记录显示所售股份从买入到卖出的加权持仓时间。多笔买入/部分卖出采用**先进先出匹配持有期限**，按对应卖出股数加权；不改变现有的**移动加权平均成本法**盈亏口径。
- **收益曲线**：按月份显示已实现月度收益柱形图、累计已实现收益折线图以及月度明细。历史盈亏采用录入的**记录日期**，并非推测实际卖出日期。
- **盈亏分成**：总览显示本人 60% 与对方 40%；每笔卖出盈亏和历史盈亏显示双方分摊，**亏损同样按比例承担**。按分取整并分配尾差，确保相加等于原盈亏。此处为账面理论分成，不反映实际资金划转。
- **CSV**：新增已实现盈亏、持仓天数、双方分成列，JSON 备份结构不变。

## 旧版本升级
1. 在旧 App 的“设置”中**先导出 JSON 备份**，保存到文件 App / iCloud Drive。
2. 将此文件夹内所有文件覆盖到原来的**同一个** GitHub Pages 仓库与同一部署路径，不要创建新的网址或改变域名。
3. 更新后重新打开 App；如仍显示旧界面，请关闭主屏幕 App 后重开，必要时在 Safari 刷新网页。Service Worker 缓存版本已从 v1 升至 v2。
4. 原数据保持 `localStorage` 键 `stockledger.pwa.v1`、JSON `version:1` 不变，旧数据和 v1 JSON 备份兼容。不应清除网站数据或删除旧 App 来升级；如更换网址或重新安装，需手动导入之前导出的 JSON。

提示：所有分析仅依据手动录入记录，不包含实时市值、浮盈浮亏、分红及未录入的交易。对日期和历史收益的不完整性请特别留意。

## v3 重要口径更正
- 历史五笔合计 ¥131,108 是**本人60%所得**，不是整体100%盈亏。历史盈亏输入框与旧版历史数据中的 `legacy[].amount` 均统一解释为**个人60%**；数据结构和本地存储键不变，无需迁移也不会自动更改旧数值。
- 由个人份额反推整体：131108 / 0.6 = ¥218,513.33（分位取整）；对方40%是 ¥87,405.33。单笔/单月独立四舍五入可能出现1分尾差。
- 新增买卖成交仍以真实成交价格和费用计算整体100%，再拆为60%/40%；累计个人份额等于历史个人份额加新增成交利润的60%。
- 收益曲线展示整体100%盈亏，历史金额按60%反推；不等同于个人60%曲线。
- 升级前导出 JSON 备份；GitHub Pages 覆盖上传时保留原网址。
